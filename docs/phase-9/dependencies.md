# PHASE 9 dependencies and operations

Node/pnpm and dependency versions remain pinned to the completed baseline. [Contracts](contracts.md) define the injected server runtime ports. The worker owns no account credentials, private order transport or HTTP trading route. It must run outside request handlers; the library composition exposes explicit start/retain/release/cycle/close rather than launching an unconfigured production process.

The deployment operator supplies a durable runtime InstrumentRegistry with the existing anti-reuse/restart contract, a metadata refresher, a shared server/IP connection/control coordinator and a bounded trade recovery implementation. Recovery must prove the native history interval; no-op/unavailable recovery cannot promote a gap to verified data. Reference registry/store in fixtures are not defaults or production readiness evidence. Future application composition and strategy consumers must retain source/data quality and require owner/readiness checks.

Apply the new additive migration with the migration identity. Provision a separate restricted LOGIN role as a member of `ctp_ingest`; do not reuse the migration owner, API, authentication or signer identity. Supply its DSN through server secret configuration, with verify-full TLS in production. The store rejects unsafe roles. There are no tenant credentials or tenant ID in public market state. Existing `ctp_api` receives only bar read access in the new schema; no checkpoint/outbox write permission.

PostgreSQL is the durable state/checkpoint/candle/outbox authority. Back up `ctp_market` with the database and monitor lease loss, version conflicts, state bytes, queue bytes/age, outbox backlog and storage latency. Plan archive/disk retention separately. A lost lease or uncertain commit stops the affected key; recreate/reconcile from committed state and require fresh source recovery. Data delivery is at least once; consumers persist event IDs/inbox before acknowledging. Shutdown stops sockets, drains committed work and releases owned leases; it does not send exchange mutations.

The 300-key fixture is a local/native-protocol loopback workload, with test/reference metadata and storage. Runtime registry certification, native exchange/IP capacity, operator recovery coverage, production database throughput and 24h soak are separate evidence. [Verification](verification.md) records only actual results; PHASE 10 is not started by this package.
