# PHASE 9 contracts

## Composition and public scope

`@ctp/market-data` exposes the candle engine, native public trade feed, WS pool, snapshot cache, PostgreSQL store and worker composition. Runtime registry, durable store, shared public rate coordinator, metadata refresh and trade recovery policy are injected server services. There is no default registry/store, raw destination/IO override in the production factory, credential or tenant argument, private stream, mutation, authorization or risk implementation. The registry owner still must prove [durability/anti-reuse](../instrument-registry-lifecycle.md); structural typing and the reference registry in tests do not certify a production implementation.

Public identity is exchange/market/environment/region/instrument. Refcounted intents share one source within a worker; PostgreSQL leases fence competing worker owners. Deployment assigns intents to the worker owning that lease. The composition module runs independently of API routes and may run in a dedicated process. `start()` drives a 250ms scheduler; callers may drive deterministic `cycle()` instead. Metadata refresh is attempted every 15s and lease renewal every 3s; each external call has a deadline. These ports must settle their underlying work after cancellation. Unknown store commitment blocks the affected key; it requires owner/checkpoint reconciliation or worker recreation, never blind replay of an uncertain commit.

Native batch trades reuse completed adapter normalizers through explicitly read-only `/market-data` subpaths. Existing adapter top-level export shape and all private/order factories are unchanged. Profiles are selected from the existing fixed catalog: Binance Spot/USDM, Bybit Spot/linear, OKX Spot/SWAP and HTX Spot/linear. Only their public trade channels are pooled. Current setting is at most 100 topics/socket and 32 sockets/process; these are conservative configuration limits, not evidence that HTX permits any arbitrary number of topics. Binance Spot uses actual `trade`, not minute bars; USDM uses native aggregated trades. Bybit Spot requests contain at most ten topics; OKX arguments and acknowledgements remain topic scoped; HTX gzip and individual ACKs are bounded. Native aggregated feeds preserve unavailable execution counts. Contract quantities are converted only using a fresh immutable BASE face-value record. Inverse/unknown quantity semantics fail closed.

Every connection/control frame passes the mandatory server/IP limiter. Native control concurrency is <=8, frame/gzip output <=1MiB, JSON depth <=32, trade arrays <=512 and before-ACK buffering <=128 frames/1MiB. TLS uses fixed server URLs, no redirects or credentials. Establishment deadline <=5s; abort terminates the actual WS/TCP operation, and capacity remains held until its promise settles. Quiet source watchdog is 45s, Bybit/OKX heartbeat 20s with 10s response deadline. Metadata expiry/replacement also invalidates quiet sources. Source close, failed ACK, malformed frame, native gap and reconfiguration cause resync; old generation callbacks cannot publish into the new generation. Full jitter backoff is capped at 30s and resets after a stable minute. Long-lived socket lifetime is naturally bounded by fresh metadata replacement/expiry, not an unbounded promise.

## Event time, quality and recovery

One granular trade stream produces UTC half-open 30s/1m/3m/5m/15m/30m/1h candles. A boundary trade belongs to the next interval. OHLC uses event time with lexicographic scoped identity tie-breaking, independent of arrival order. Decimal arithmetic is exact within the existing Core 30+18 aggregate envelope; over-scale/range is a gap, never rounding. Trade identity includes public key + native identityScope + tradeId; receivedAt is excluded from replay fingerprint. Identical replay is ignored; conflicting identity invalidates the candidate batch. Execution count is nullable when a native aggregate does not prove individual executions.

Valid exchange event time advances a monotonic watermark with a 2s reorder allowance. This can publish an **UNVERIFIABLE** partial candle, never complete=true. Complete bars require trusted `CONTIGUOUS_NATIVE_SEQUENCE` or `RECONCILED_TRADES` coverage of the whole interval, with no remaining gap. Binance Spot consecutive native trade IDs can establish coverage after the first observed trade; an initial prefix remains unverified. Other pooled channels do not fabricate a universal sequence +1 proof. Injected recovery must provide bounded normalized trades and explicit coverage evidence; unavailable/truncated/unprovable history remains GAP. Recovery accepts at most 2048 trades per key per attempt and processes at most four keys per cycle. A timer, subscription ACK, connected socket or heartbeat is not a coverage proof.

Verified empty intervals have null OHLC and no Core Candle; they are `EMPTY_VERIFIED`. Outages are `GAP`, not zero-volume bars. Late input within the correction horizon produces a new revision and `CANDLE_REVISED`, not a second historical trading signal. `LATE_CORRECTION` is incomplete until explicit reconciliation validates it. Partial gap repair removes only the proven interval; remaining missing history survives. Late reconciliation may improve coverage without decreasing the watermark. Replayed old coverage cannot recreate pruned populated history as empty bars.

The hot correction/dedup horizon is 60s behind the persisted watermark. Each key has <=2048 identities, <=256 bars and <=128 coverage/gap ranges; checkpoint <=512KiB. Eviction advances a durable event-time admission floor: old replay is rejected instead of being accepted again. This does not alter the registry's permanent version anti-reuse invariant. A correction older than the admitted horizon needs an explicit dataset rebuild/revision workflow; this worker cannot silently revise archived history. Daily/history retention and PostgreSQL storage capacity require an operator policy; memory bounds are not a disk-retention promise.

Global queue <=50,000 items or 32MiB, including in-flight items; state default <=128MiB. Overflow creates an explicit gap and does not evict live cursors/IDs. Work batches <=2048; aggregation yields every 32 inputs and after each key. One key's malformed data/storage failure does not authorize dropping others. Health requires recent valid data; restart and gap are stale until recovery. Source heartbeat alone cannot make a feed fresh.

## Snapshot and persistence boundaries

The optional bounded market snapshot cache consumes normalized ticker/book snapshots from the existing public adapter streams. It refuses DELTA input: native assemblers/continuity/checksum and fresh resnapshot remain adapter responsibilities. Numeric book sequences compare through BigInt; absent native versions use exchange time, duplicates require identical semantic payload, conflict/regression clears the book. Stale/replaced metadata, malformed known-key input and gap also clear cached data. This is a defense after native guards, not a replacement for them. Cached books are never restored from a checkpoint as healthy after restart. Pooling native trades does not imply that 300 native order-book streams have been accepted or benchmarked.

New additive migration `202610040001_market_data` creates isolated `ctp_market.partition`, `.bar`, `.event`. Existing published migrations/tables/financial constraints remain intact. The separate bar envelope can represent missing OHLC and quality that the PHASE 2 `public.candle` schema cannot represent; no fabricated nonnull price/quote volume is inserted there. Future consumers use the PHASE 9 dataset contract explicitly, not an assumed alias of the old table.

Only a restricted `ctp_ingest` login may use the market store. Startup rejects superuser/bypass/owner/API/auth/signer/inherited privileged roles and financial/secret grants. API gets read-only bar access, no checkpoint/outbox mutation. Server DSN is never sourced from an HTTP body; production requires verify-full TLS. Pool <=4, connect <=1s, statement <=2s, query <=2.5s, operation <=3s. Abort destroys a blocked query's owned connection. PostgreSQL clock decides the 10s lease; owner epoch is a lossless decimal string and survives restart. Acquisition locks the partition; commit requires owner+epoch+version+unexpired lease.

One transaction commits state/dedup/checkpoint, archived candle revisions and durable public outbox. SHA256 CHECK protects checkpoint bytes. Equal candle revisions require identical payload; regressed/conflicting archive writes roll back the whole transaction. Outbox <=10,000 events/key; saturation blocks the producer until delivery/acknowledgement. Events have stable UUID identities, ordered delivery and explicit acknowledgement, at-least-once semantics. Downstream consumers must persist their own inbox; no exactly-once external delivery is claimed.

## Evidence and limitations

Official native protocol sources checked during implementation: [Binance stream limits](https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md), [Bybit public connection/topics](https://bybit-exchange.github.io/docs/v5/ws/connect), [OKX WebSocket guide](https://www.okx.com/docs-v5/en/), [HTX Spot trade stream](https://huobiapi.github.io/docs/spot/v1/en/). Native normalizer semantics and private limitations remain in PHASE 5–8 contracts. The 300-key loopback benchmark is a bounded test fixture, not a 24h soak, a native exchange capacity certificate or production SLO acceptance. Extended multi-exchange production load/soak remains PHASE 20. LIVE trading is disabled.
