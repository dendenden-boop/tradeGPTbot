## Установка и аудит

[Политика pnpm](../../pnpm-workspace.yaml) сохраняет `saveExact`, `strictPeerDependencies`, `engineStrict` и минимальный возраст релиза 1440 минут. Native install разрешён явно для `argon2@0.45.1` через `allowBuilds`. Сборка и развёртывание используют зафиксированный lockfile; обновление этих версий требует повторной проверки графа, native-модуля и production deployment.

Снимок `pnpm audit --json` от 20 сентября 2026 года: **0 известных уязвимостей среди 404 зависимостей**; все уровни severity равны нулю. Машинный результат сохранён локально в `test-results/phase-3-dependencies.json`. Это результат проверки указанного графа на эту дату.

## Параметры Argon2id и измерение

[PasswordHasher](../../packages/auth/src/password.ts) использует Argon2id v19: память 65 536 KiB (64 MiB), три прохода, parallelism 1, результат 32 байта. Одновременно выполняются не более двух native-операций, ещё восемь могут ждать в очереди. Слот сохраняется до фактического завершения native-вызова. Для неизвестного аккаунта проверяется заранее созданный dummy hash; параметры сохранённого PHC проверяются до запуска native-кода, чтобы повреждённый хеш не задал произвольную стоимость.

Повторяемый локальный замер 20 сентября 2026 года: Windows x64, Node 24.20.0, Intel Core i5-9300H, 7 последовательных измерений. Hash p50/p95 — 139/142 мс; verify — 139/140 мс. Два параллельных hash завершились за 173 мс; максимальный RSS процесса — 200 716 KiB. Инициализация dummy hash — 144 мс. Снимок: `test-results/auth-benchmark.json`; CI запускает тот же скрипт на Windows и Linux.

Повторяемый замер запускается после сборки командой `pnpm benchmark:auth`; [скрипт](../../scripts/benchmark-auth.mjs) записывает отдельный `test-results/auth-benchmark.json`. Он фиксирует оборудование, настройки, распределение времени и RSS. Эти локальные измерения не определяют производительность production-сервера под нагрузкой.
