## Content and identity

Input has only `kind: PAPER_PREPARE_UNSENT_CANCEL`, a permanent caller key, the complete immutable common Order state, and original withdrawal/release receipt content. `now` is explicit, finite integer milliseconds in the existing timestamp range. No ambient clock, metadata registry, adapter, URL, credential, random-ID allocator or authority callback is used. The calculation checks content consistency; caller-provided time, bindings and receipt objects are not trusted evidence.

Only an original pristine CREATED/version0 PAPER Spot BUY with REQUIRED reconciliation, null connection, the sealed `paper-spot-v1` / `spot-l2-taker-v1` SIMULATED profile and no credential reference is supported. Its MARKET/LIMIT command must agree exactly with the original draft and retained PLACE hash. No effective amendment, attempt, active operation, exchange identifier/observation, fill, execution/notional or average fill price is allowed. Original PLACE command/draft/client ID are immutable. Other states and execution profiles fail closed; native modes remain on their existing path.

Strict withdrawal/release shapes retain the existing NOT_SENT/RETAINED then NOT_SENT/RELEASED version1 content. Exact Order, PLACE intent, decision, reservation, book and command identities must agree. Release must name the original withdrawal event, have a distinct event ID, contain the supported single positive debit and move the causal book revision forward. Revision strings are compared losslessly with BigInt within their accepted range; unrelated intervening book revisions are permitted. Original creation, withdrawal and release timestamps must be ordered and not future-dated against explicit `now`. Unknown fields, missing/conflicting content and unsafe/noncanonical revisions reject.

The immutable output is tagged `PAPER_UNSENT_CANCEL_PLAN`. Its semantic request is `{binding, orderId, operation: CANCEL, key}`. `requestHash` is the common permanent-cancellation semantic hash of `{binding, orderId, operation: CANCEL}`; the key is stored separately in the permanent namespace. Changing the key does not allocate another client ID or alter target command semantics. Changing account/target changes that semantic hash. The command is the existing common cancellation locator `{instrumentId, locator: {kind: CLIENT_ID, id: originalClientOrderId}}`, without invented native target timestamps or exchange IDs.

PAPER command hashing follows the existing PAPER PLACE domain: `hash({operation: cancelOrder, command, binding})`. Native `computeCommandHash` requires a real connection and cannot hash PAPER/null connection. No fake connection or native credential is introduced. The output retains the original PLACE hash and canonical withdrawal/release content digests, plus a proposed CREATED→CANCELED/version0→1 descriptor with source `PAPER_NOT_SENT_CANCEL`. These hashes and the descriptor are content, not proof of issuance, completeness, ownership, a durable transition or permission. The plan has no allocated CANCEL intent/event ID, result receipt, outcome, public Order state, ledger posting or grant. JSON reconstruction does not certify it.

## Durable bridge remains required

Public CANCEL completion remains unimplemented. A future narrowly authenticated PostgreSQL bridge must re-read private issuance/barrier/release provenance, the common immutable PLACE and current ownership/permissions under the existing lock order. It must perform authoritative permanent-key lookup before preparing a new target, so replay of an already accepted key does not require a still-pristine current Order or current metadata. Exact replay returns the original durable result; changed target/account/semantics conflict.

That bridge must atomically create a genuine common immutable CANCEL intent and terminal Order/event/outbox with narrowly permitted private cause, while preserving the original PLACE, all collateral tombstones and financial history. The published withdrawal guard rejects all late control intents/Order mutations; a general guard bypass, GUC flag, fabricated native acknowledgement, cancel+create or raw caller receipt is not an acceptable bridge. UNKNOWN cannot become NOT_SENT. Race/restart/lost-COMMIT/private-role acceptance and no second monetary effect are prerequisites. No such exception or writer is added here.
