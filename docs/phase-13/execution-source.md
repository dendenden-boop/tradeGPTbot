## Request, ordering and completeness

`read(request, io)` accepts exactly `kind: PAPER_EXECUTION_CAPTURE`, original admission `{ binding, orderId, intentId, operation: PLACE, commandHash }`, and current `authorization: { permissionEpoch, userSessionEpoch }`. Binding and authorization epochs must be constructed after server authentication. UUIDs, epochs, caller JSON and possession of a plain read result do not authenticate a human principal. Database credentials remain server configuration, with the existing strict URL/TLS/role checks; no SQL/client/role callback or user endpoint is accepted.

The fixed reconciliation RPC holds GLOBAL shared → tenant → verified user → sorted complete PAPER account catalog → Orders → causal books/reservations. It checks exact active ownership/profile/epochs and invokes the existing complete tenant inventory validation. Missing or conflicting histories, UNKNOWN, attempts/fills/positions or unsupported economic state reject the complete read. Unissued drafts cannot become executable contenders. An actual immutable private NOT_SENT barrier excludes its target without releasing its hold; a withdrawn requested target rejects. A status label or caller receipt cannot establish that exclusion.

Before invoking the published inventory helper, capture requires an existing causal head for **every** tenant PAPER account. That helper can adopt a pristine book when used by admission; a reader must not initialize even another account. Consequently a funded but unadopted secondary account blocks this initial capture. This is an explicit conservative limitation, not permission to hide an account or infer a new head.

Contenders are ordered by their original immutable admission certificate revision from the durable non-cycling admission sequence. It is independent of draft creation time, array order and timestamp ties. Positive signed64 integer strings remain lossless above 2^53; reads allocate no sequence or priority. The source rejects more than 300 eligible contenders instead of truncating them. Duplicate identities/hold IDs, reversed priorities, stale rules or incomplete/mismatched target content reject.

Each descriptor retains original order/intent/reservation/decision identities, command/hash, DB instrument/rule identity, original admission time, certificate/source references, historical expiry, execution bounds and original debit/hold identities. `admittedAt` is historical admission time, **not** evidence that transport started; no `submittedAt`, fill, ACK or transport timestamp is invented. Historical approval expiry is never renewed by the current market freshness deadline.

## Market, Portfolio and authority boundaries

Current metadata and native snapshot/trade heads are read under the existing catalog SHARE locks and validated against original public publications. The stricter current policy/model freshness age is used. Original receipt times and hashes remain; no snapshot is resealed. Schema/current rule validation, public scope, metadata identity, stale/GAP/future evidence and current model consistency fail closed. This is market/input capture, not a new capability/control/health certificate or Risk evaluation.

Portfolio must be the original reconciled cash-only book plus authenticated reservation/lifecycle history. Its balances, original snapshot time, all retained holds, revision and hash remain unchanged. No positive native credit, hold release, monetary posting, counter increment or outbox write occurs. The source does not support an executed/non-pristine book: the future durable writer needs a separately accepted history/consumption contract rather than relaxing this guard.

The output `PAPER_EXECUTION_SOURCE` is deeply immutable and contains current capture/freshness times, original configuration/funding/model, Portfolio and book reference, market evidence and the complete candidate descriptors. Its ordinary hash is correlation only. It is not a grant, permanent execution receipt or liquidity allocation. Repeated reads cannot authorize reusing a native trade or resetting volume. A future fixed writer must reread complete authoritative state atomically, enforce current Risk/authorization/controls/deadline and ACTIVE reservation, retain the durable attempt, and commit permanent fill replay/shared allocation/ledger/Portfolio/order/holds together. Caller JSON and source freshness cannot substitute for that boundary.

The existing four-slot physically settling admission transport is reused. The factory calls only reconciliation, returns evidence after known COMMIT and physical cleanup, and rechecks the caller deadline plus source freshness. Abort/close drain underlying operations. A lost COMMIT returns no evidence; a deliberate readonly retry may recapture current state without a monetary retry or new identity.
