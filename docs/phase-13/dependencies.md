# PHASE 13 dependencies and operation

The initial `@ctp/paper-engine` pure calculator reuses existing pinned `@ctp/exchange-core`, decimal.js 10.6.0 and Zod 4.5.4. Only a workspace importer is added to the frozen lock; no new external package, version, integrity, build-script allowance or release-age exception. SHA-256 provides deterministic domain-separated seed sampling, not authentication or credential encryption.

Only compiled public calculation/schema exports are deployed; source/tests, testing subpaths and memory financial stores are excluded. The clean-install check adds a twelfth isolated production deployment and exercises actual public imports, input rejection and absence of grant/mutation authority. Ancestor node_modules resolution remains forbidden.

The initial calculator checkpoint added no database authority. The configuration increment adds migration 35, private configuration receipt storage and an isolated `ctp_paper_configuration` server role. Published migrations 1–34 and native adapters/Order/Risk/Portfolio/application routes remain unchanged. Its compiled `/configuration` subpath reuses existing pinned pg 8.23.0 / types 8.23.1; only that workspace importer changes, with no new external resolution or integrity. Provision a separate restricted login with only this NOLOGIN membership; no other runtime role receives it automatically. Startup and SQL independently enforce the boundary. A production/staging server-controlled URL requires verify-full TLS. No HTTP route, account provisioner, financial writer or credential port is introduced. Clean deployment checks the compiled subpath and rejects source/testing imports.

Production PAPER dispatch remains disabled until durable account/ledger, same-gateway Risk/Portfolio and worker acceptance is complete. A calculator checkpoint is serializable deterministic input, not durable financial state or certified source evidence. The immutable configuration receipt is durable model identity only; it cannot authorize funds or execution. Retain the private receipt with the account and future ledger in backups; never recreate a missing receipt from mutable public display records.

Backups for the eventual PAPER runtime must retain complete model/seed/reset epochs, funding and monetary journal, order/Intent/reservation/hold histories and native event/ordering/liquidity allocation history together. Rebuilding from only balances or resetting consumption after restart is invalid. Dedicated least-privilege roles and populated upgrade/restart/concurrency tests are prerequisites before exposing financial operations. No live credential port belongs in Paper composition.

The model is a conservative simulation and cannot establish real exchange execution outcomes or performance. No exact maker queue/priority, derivatives, public-feed production soak or real private exchange acceptance is claimed. LIVE and positive native collateral credit remain disabled; accepted narrow Binance Spot TESTNET native AMEND is unchanged.

The additive integrity hardening introduces migration 36 and private `configuration_seal`. Keep configuration, seal and account identity together in backups. Missing seals or disagreement fail closed; restore must not synthesize a fresh seal from mutable display data. Published migration 35 is retained byte-for-byte. No new external dependency or runtime role/function grant accompanies this hardening.
