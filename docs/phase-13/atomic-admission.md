## Fixed server boundary

The intended server-only `createPostgresPaperOrderRiskPort` accepts strict server database configuration, environment and constructor AbortSignal/deadline. It cannot accept a snapshot, source, certificate, evaluator, grant, policy bypass, tenant override, exchange endpoint/credentials, client, role, RPC or SQL override. It is not yet exported from the server risk subpath or pure root. The internal transport fixes role `ctp_paper_risk_admission` and RPCs `ctp_paper.evaluate_and_reserve(jsonb)` / `ctp_paper.reconcile_admission(jsonb)`; those SQL boundaries and their additive migration are not implemented yet. No application composition uses this component.

The transport owns each physical socket before connect, bounds pending work to four without a queue and retains a slot through physical/query cleanup. Operations use a bounded transaction, connection/statement/query/session deadlines and original caller cancellation. Failed cleanup quarantines the driver. COMMIT dispatch followed by connection loss, abort or uncertain cleanup returns no result and no usable grant. Reconciliation is an explicit read; neither MISSING nor an expired historical receipt authorizes mutation retry or release. No mutation is blindly retried.

The SQL role must have only its fixed guarded RPCs: no table/column access, alternate runtime role memberships, schema ownership/CREATE, database CREATE/TEMP, elevated privilege or unrestricted helpers. Constructor role checks and a mocked successful role response are not proof of actual SQL privileges. The migration must define and test this boundary with real PostgreSQL before export.
