## Server contract

`createPostgresPaperAttemptJournal` is exported only by `@ctp/paper-engine/risk`. Its fixed PostgreSQL transport retains the existing bounded transactions, physical abort/settlement, four pending slots, private errors and uncertain-COMMIT behavior. The role retains only `ctp_paper.evaluate_and_reserve(jsonb)` and `ctp_paper.reconcile_admission(jsonb)`; caller SQL, credentials, endpoints, attempt IDs, commands, timestamps, permits and result objects are not request fields.

`prepare()` accepts a permanent preparation key, exact issued PLACE binding/order/intent/command hash and current server authorization epochs. PostgreSQL generates the UUID and preparation time. For a new key it authenticates the complete pristine execution source, causal tenant Portfolio/holds and current metadata/public market evidence, requires original admission expiry still in the future, and writes one immutable PREPARED descriptor. Original command, decision, reservation, metadata identity, admission priority/time and expiry remain unchanged. No book adoption, reservation renewal, client ID, public order update or monetary write occurs.

Current ownership, account/user state and authorization epochs precede every lookup. The permanent semantic key excludes changing authorization epochs. An exact replay returns the original PREPARED result after rule replacement or expiry, including when a later NOT_SENT exists. Replay is historical content and cannot renew authority. A different semantic request with the same key, or another preparation key for the same intent, conflicts. `read()` exposes the original preparation and current journal head, or MISSING without creating anything.

`stopBeforeStart()` requires the original preparation key and an independent permanent stop key/reason. In one transaction it calls the existing private withdrawal kernel, writes its actual irreversible NOT_SENT barrier and records revision2 against that event UUID/time. An already committed legacy withdrawal may provide the same authenticated negative cause. It never creates a second barrier or releases collateral. STOP and UNKNOWN serialize through the existing GLOBAL → tenant boundary; UNKNOWN cannot be downgraded. The retained hold remains subject to the separate accepted withdrawal-release and unsent-cancellation lifecycle.

`reconcileStop()` reads the exact stop key. It cannot create a stop or infer one from the absence of an attempt. Any uncertain mutation COMMIT returns no result; recovery uses these read-only methods, with no automatic mutation retry. Missing/stale/contradictory scope or evidence fails closed.

## Persistence and boundary

Additive candidate migration59 creates `ctp_paper.attempt_preparation` and `ctp_paper.attempt_not_sent`, with permanent uniqueness, forced tenant RLS, immutable UPDATE/DELETE/TRUNCATE guards, retained hashes and actual issuance/withdrawal cause checks. Only the relationship between the two new journal tables uses a foreign key. Adding a referencing FK to the already immutable published tables would intercept their established BEFORE TRUNCATE error; the retained causal checks authenticate those relationships without changing that contract. It backfills no attempt. Private aliases preserve the two published58 RPC bodies and settings. Published migrations1–58 remain byte-identical. Populated58 deploy/redeploy, original function/row retention, non-BYPASSRLS owners and isolated reset are mandatory CI evidence.

The journal accepts no START, UNKNOWN attempt, ACK, fill or positive resolution. The existing pure START/UNKNOWN protocol remains content only. A future execution writer still needs current Risk/policy/control/health/rules validation, one-use handoff and an atomic financial outcome. Calling the execution source at preparation is not that final gate. LIVE/PAPER financial dispatch and positive native collateral credit stay disabled; native AMEND remains Binance Spot TESTNET only.
