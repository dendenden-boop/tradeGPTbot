## Spot L2 taker model v1

Model identifier `spot-l2-taker-v1` binds signed 64-bit seed, quote taker fee, maximum adverse slippage, minimum latency/jitter, observed volume participation and evidence freshness. Seeded values derive from SHA-256 of model configuration, stable order ID and a domain-separated purpose; slippage additionally binds the immutable native evidence identity. No global PRNG or wall-clock sampling. Model arithmetic uses the existing decimal envelope and pinned Decimal implementation; liquidity and quantity round down to lot step, BUY execution prices round up to tick, SELL down, and quote fees round up to 18 decimal places. Overflow fails closed rather than silently losing precision.

Each frame requires one fresh complete noncrossed L2 snapshot and one real base-unit trade tick in exact market/instrument scope and current rules. Native trade identity plus payload hash is permanent durable replay identity in the eventual worker. Book sequence is compared losslessly by the upstream Market Data contract; the calculator consumes complete evidence, not stream deltas. Empty sides, missing native ordering, stale metadata, stale/future exchange or received time and inconsistent evidence reject. A frame is not a trusted Market Data certificate.

Frame liquidity is shared across all competing orders for this public source/instrument/trade identity within one server-owned virtual account/reset epoch/model scenario. Separate virtual accounts simulate separate scenarios; their funds and liquidity journals must never cross tenant/account boundaries. Its total allocation cap is trade base quantity × participation, rounded down to the lot step. Each depth level has its own quantity × participation cap. BUY and SELL share the total volume cap. Returning the next frame reduces both caps exactly; it never creates another frame or resets the budget. The eventual durable worker must enforce immutable event identity, ordering, replay and persistence; callers cannot reset budgets to obtain new financial authority. A new book with the same trade identity cannot grant fresh trade volume. A pure caller-provided checkpoint is not a production concurrency/replay guard.

Only Spot base-quantity MARKET/LIMIT/STOP_MARKET/STOP_LIMIT, with GTC/IOC/FOK, are modeled here. POST_ONLY, quote budgets, derivatives and MARK/INDEX stops reject. This model claims taker execution only: resting limits fill only against subsequent executable book evidence, paying taker fees; it does not infer queue position from L2. FOK uses a dry-run across all eligible levels and changes no liquidity if the whole remaining order cannot fill. IOC fills what is available and expires the remainder. Market remainder expires; it never retries on a later invented price. GTC can remain partial.

Execution requires both trade and book evidence after modeled eligibility time, and not later than the explicit evaluation time. Stops use LAST trade evidence: BUY activates at/above trigger, SELL at/below; durable triggered time is sticky and must be after submission eligibility. Triggering does not invent liquidity. Explicit TP/SL/bracket semantics and durable activation are required in the gateway increment; they are not claimed by this calculator.

Slippage applies adversely to observed executable depth, then tick rounding; the resulting price must satisfy limit and instrument price bounds. Each fill records stable identity, quantity, price, quote notional/fee and exact base/quote deltas. Fees are charged once in quote currency. Balanced virtual accounting must pair deltas with external execution and fee counterentries; no second PnL ledger effect. The calculator does not assert wallet affordability or a Risk execution-price bound; production must enforce both before commit.

The certified PAPER execution-price bound must include adverse slippage and tick rounding, not only the current reference price. Its fee bound must also cover quote rounding for every possible minimum-lot fill: rounding each slice upward can exceed rounding a single aggregate commission. If a conservative representable price/fee/reservation bound cannot be established, admission must reject. A calculator result cannot top up a reservation or debit an unreserved balance to compensate for an underestimated bound.

## Outstanding durable contract

The separate `@ctp/paper-engine/configuration` subpath persists a server-selected immutable model receipt for an already provisioned, active PAPER account. This is configuration authority only: it creates no account, funding, balance, order, reservation, grant or transport permit. The calculation root stays pure. The caller derives tenant/account from authenticated server ownership and selects source/model; this port is not an HTTP authorization API. Never pass request-body tenant, credentials, endpoint URLs or model configuration directly to it.

Additive migration 35 introduces private `ctp_paper.configuration` with tenant FORCE RLS, immutable UPDATE/DELETE/TRUNCATE guards, one permanent configuration per account and globally unique receipt ID. Isolated NOLOGIN group `ctp_paper_configuration` has only `register_configuration(text)` and `read_configuration(jsonb)`. Startup rejects elevated/transitive/mixed roles, schema ownership/CREATE, public/private table/column privileges and extra private functions. SQL independently checks the runtime role, exact known fields, decimal/seed/latency limits, transaction-local tenant and current active verified ownership. Registration locks receipt ID, tenant and account in that order, without monetary/budget locks. Source exchange/region must match the account's SIMULATED profile; source market is SPOT and its public environment stays distinct from PAPER mode. Published constraints still forbid PAPER private connections.

Exact ID/account/configuration replay returns the original receipt and timestamp after restart. Changed ID, model, source or valuation asset rejects; an ID cannot migrate to another account/tenant. Read rechecks current ownership/status/profile plus frozen external account/client epoch identity. Missing configuration, disabled/suspended ownership or changed identity fails closed. No backfill trusts mutable public `paper_account` records. Reset, reconfiguration and funding require later explicit lifecycle contracts and have no entrypoint here.

The receipt checksum detects corruption; it is not an authentication signature, Risk certificate or freshness proof. The port owns the PostgreSQL socket before connect, bounds operations to four without an unbounded queue, and destroys sockets on abort/deadline/close. Only acknowledged COMMIT returns a receipt; ambiguous COMMIT yields `PAPER_CONFIGURATION_UNCERTAIN`, without automatic retry. Explicit same-key read/replay resolves configuration publication. This proves configuration persistence only, not monetary execution or event/liquidity consumption.

Migration 36 adds an independent immutable receipt seal. Hashing a stored receipt anew on every read proves only wire consistency and cannot detect storage disagreement with the original model. Insert now seals the exact original text in the same transaction; read/replay require the retained seal, exact tenant/account, coherent ID/request/receipt and original hash. Missing/conflicting/corrupt evidence rejects with `PAPER_CONFIGURATION_CORRUPT`; no repair derives a fresh hash from changed data. The upgrade validates existing request/receipt agreement before sealing and preserves original timestamps/text. A non-BYPASSRLS owner uses transaction-private maintenance policies under an exclusive configuration lock; both policies are dropped before COMMIT. No runtime grants or monetary writer are added.

PAPER account has exact tenant/account/mode ownership and no private connection. Funding/reset epochs, permanent Intent keys, immutable model versions, current policy/registry certification, shared liquidity allocation, conditional activation, cancel/fill races, pause ordering, lost-COMMIT resolution and same-transaction Portfolio posting remain required. PAPER isolation must survive restart and deny access to all native credential/financial authority roles. Additive migration, role graph, deployment and populated upgrade proof are required before enabling this path. See [requirements](requirements.md) and [verification](verification.md).

Concrete compatibility gaps were inspected, not bypassed: [Order binding](../../packages/order-engine/src/domain.ts) uses null connection for PAPER and [Order service](../../packages/order-engine/src/service.ts) rejects its native dispatch. The initial-only source addresses the earlier UUID-only [Portfolio binding](../../packages/portfolio/src/domain.ts); its [native PostgreSQL store](../../packages/portfolio/src/postgres-store.ts) rejects PAPER rather than joining a dummy exchange connection. [Production admission](../../packages/risk-engine/src/postgres-admission.ts) and published certification SQL still reject PAPER. Existing public PaperAccount/PaperOrder/PaperPosition records alone certify neither model configuration nor financial authority. Full PAPER Risk/Portfolio reservation and dispatch remain outstanding; no fake RiskGrant is issued.
