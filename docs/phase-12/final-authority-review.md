## Direct mutation and SQL review

Repository-wide production call search found only Order Engine service calls to adapter.createOrder, adapter.amendOrder and adapter.cancelOrder. Trading packages are not routed from the HTTP API; strategy/TWAP/rebalance/Paper entry points are future work and must use the same gateway. No direct protocol transport/signing/network implementation is exported by an exchange package. Server-controlled endpoints, credentials, identity resolvers and sandbox authorization are trusted composition dependencies, not values accepted from a client DTO. Arbitrary trusted JavaScript can perform I/O; the claim is about repository production paths and accepted ports, not an impossible sandbox around developer code.

OrderStore.authorize accepts only createOrder/cancelOrder/amendOrder, recomputes the exact scoped command hash and consumes a matching durable attempt. setLeverage, batch cancellation and unclassified operations have no certified Order/Risk grant. The current_dispatch_trigger calls private validate_dispatch for every new transport start, including direct SQL. Published permit constraints prevent separate, repeated, rewritten or future timestamp consumption. Native tests cover direct execution policy bypass, extra Risk EXECUTE authority and fabricated exposure/loss/hold projections.

The exact startup allowlists cover all ctp_* namespaces, PUBLIC function ACLs, pinned SECURITY DEFINER search_path, table/column/CREATE/ownership and transitive grouping-role membership. Native role regression includes 115 cases and a non-BYPASSRLS DDL owner. The new read-only observer adds no SQL function grant, role or migration. No source-path SAST exclusion or query suppression is added.

## Accepted limitations

- LIVE remains disabled in Order service and production authorization. This phase adds no public trading endpoint or production exchange mutation acceptance.
- Native AMEND is limited to Binance Spot TESTNET standalone LIMIT/GTC quantity reduction at unchanged price with stable native order ID and server client-ID replacement. Other profiles remain UNSUPPORTED; HTX trading remains denied.
- Conservative native free/available minus full local hold can underestimate spending capacity. Positive native credit is disabled by explicit user decision; there is no duplicate monetary ledger posting or logical exposure.
- Real PostgreSQL with controlled protocol HTTP responses proves repository authority and native mapping; it does not prove live/private exchange account acceptance or a production 24-hour soak.
- The inspected GitHub branch-protection/rules APIs reported no protection. Required OS/native/Docker checks are executed and verified, but administrative enforcement/no-bypass is a manual operational requirement, not claimed as configured.
- Password-only ADMIN/requiresMfa interactive login remains unavailable and fail-closed until a complete MFA flow is implemented.
