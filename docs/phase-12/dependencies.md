## Coordinator reconstruction dependency

RiskSnapshotStore is mandatory server-owned runtime injection, with no exported memory fallback. Its PostgreSQL implementation and the durable market/FX/health/UTC source collectors remain outstanding; the service contract alone must not be installed as production Risk authority. The backend must validate all current source heads and exact owned same-mode inventory under one bounded READ COMMITTED transaction, preserve immutable certificate/revision history across restart and terminate the physical connection on abort/deadline. Source hashes and valid UUIDs do not authenticate a source or tenant. No extra SQL authority, monetary writes or migrations are granted by the reconstruction increment.

The first increment is `@ctp/risk-engine`, a server-only pure library built with the existing pinned Node.js 24.20.0/TypeScript toolchain. It depends on existing `@ctp/exchange-core` and Zod 4.5.4; no external version or supply-chain policy changes. The lockfile adds only the workspace importer. Clean production verification includes a separate eleventh isolated deployment, compiled public exports, rejected malformed input, absence of test/source files and absence of RiskGrant/transport authority exports.

The pure evaluator has no connection string, network endpoint, credential, clock timer, database writer or exchange mutation. It accepts the complete evaluation time explicitly and requires both platform and user limits. Structural validation does not certify a principal, snapshot source, FX, execution-price bound, fee model or persisted policy version. Server provisioning of these inputs remains a required future PHASE 12 module.

The controls increment adds the existing pinned pg 8.23.0 and @types/pg 8.23.1 to this workspace importer, without introducing a new external version. createPostgresControls uses server-controlled connectionString/environment/authority. GLOBAL requires ctp_risk_operator; TENANT requires ctp_risk_control. These are NOLOGIN restricted group roles; deployments provision separate nonprivileged login credentials and grant exactly one group. The startup guard rejects owner/API/auth/ingest/Portfolio/execution identities, role mixing, direct table grants, schema/database CREATE/TEMP and additional control-function authority. Production requires verify-full TLS; test requires loopback. No user-supplied connection string, scope authorization or credential is routed into this factory.

New migration 202610050003_risk_controls owns the ctp_risk sidecars/functions, tenant FORCE RLS, immutable events, nondeletable monotonic heads and compatibility ordering triggers. It does not rewrite the nine published migrations or backfill monetary state. Fresh deploy, upgrade and reset initialize GLOBAL as PAUSED. There is no production auto-resume script: an authorized operator must inspect source health and reconciliation, then explicitly record a current-epoch update with reason/evidence. Only isolated test fixtures open their gate. HALF_OPEN is observable probe state, not order permission. The storage API itself does not certify that probe evidence is trustworthy.

SQL pools have four connections, 1s acquisition, 2s statement/2.5s query and at most 3s transaction deadlines; abort destroys the actual connection. No callback holds a SQL transaction across exchange I/O. Observability reads bound SQL aggregation to 10001 rows and reject beyond 10000 per set; they are not certified admission snapshots. Read failure or uncertain commit never grants permission. Reopen/read or replay the same immutable control event to inspect committed outcomes; do not advance an epoch based on an uncertain response.

Backup/restore must retain complete heads, immutable event history, function ownership/ACLs and tenant RLS together; heads alone lose permanent replay evidence. Controllers cannot truncate/delete/overwrite history. There is no TTL auto-resume or restart reset. Existing public pause/circuit records remain extra conservative blockers and their writes acquire the same durable gate. Engine final authorization uses shared global/tenant locks before account locks and holds them through one-use consumption/COMMIT; pause takes the corresponding exclusive lock. Readiness cannot be inferred from an earlier observed RUNNING row.

Before acceptance, the durable Risk gateway still needs stable shared budget locks and certified Portfolio/Market Data snapshots to reconstruct restart and UTC loss baselines, preserve permanent reservation ownership and avoid double accounting. AMEND still needs native capability mappings, separate immutable intents/attempts and positive revision-aware recovery. None of these is represented by a process-local mock in the production package.

Existing Order Engine requires a durable RiskGrant and continues rejecting LIVE dispatch. The pure result cannot be used in that port. Paper simulation and future strategy/UI implementations are outside this increment. Final current-policy/state certification, independently proved cancellation/reduction exceptions and certified circuit probe/recovery remain mandatory before READY FOR PHASE 13.

Position-mode/currency hardening adds no dependency or migration. Native profile/metadata fixtures are tests only and remain absent from production exports. Execution startup checks the complete ctp_risk function catalog by OID, allowing only dispatch_gate(uuid,uuid); unexpected direct, inherited, PUBLIC or overload execution privilege rejects before the store opens.
