# PHASE 12 supply-chain verification

The normal Ubuntu/Windows workflow retains frozen installation, pinned Node/pnpm, original Action commit pins and the HIGH/CRITICAL dependency gate. Added source scanning and reports require acceptance on their exact source SHA; local output alone is not CI acceptance.

`audit:secrets` scans all tracked source files without excluding tests. It rejects recognized GitHub, AWS and Slack credential signatures, private-key headers and tracked environment files other than the existing `.env.example`. Findings include location/type only. It fails on tracked symlinks or files above its four-MiB bound, rather than silently omitting them. Ignored local credentials are not read. There is no entropy-based detection, exchange-key identification or Git history scan; provider-side scanning remains an operational complement. Tests construct inert signatures in memory and verify that reports never reproduce matching bytes.

`audit:supply-chain` invokes the pinned pnpm CLI, checks installed packages against lockfile package identities, rejects unknown license expressions and conflicting identity/license pairs, emits `licenses.json` and a deterministic `sbom.cdx.json`, then retains the full `pnpm audit --json` report. Missing/malformed audit results deny acceptance. HIGH/CRITICAL causes failure. The SBOM is a component inventory of packages actually installed on the runner's OS, including development tooling; it does not assert complete dependency edges, artifact attestation or the installation of other platforms' optional binaries. It records the exact lock hash, strips machine paths and uses the [CycloneDX 1.6 JSON format](https://raw.githubusercontent.com/CycloneDX/specification/master/schema/bom-1.6.schema.json). Contract tests validate the emitted fields; external full-schema certification is not claimed.

Reviewed installed license expressions are MIT, Apache-2.0, ISC, MIT AND ISC, BSD-2/3-Clause, BlueOak-1.0.0, MIT-0 and Unlicense, plus existing EPL-2.0 tooling `elkjs` and MPL-2.0 `lightningcss`/platform binaries. This gate preserves inventory and notice/source obligations; it is not a redistribution legal clearance. A new expression requires explicit repository policy review instead of becoming implicitly accepted.

The repository is public, and the read-only default-setup API reported `not-configured` on 7 October 2026. GitHub documents [public repository CodeQL eligibility](https://docs.github.com/en/code-security/concepts/code-scanning/code-scanning). The new separate CodeQL workflow requests only contents read and job-scoped security-events write, uses JavaScript/TypeScript without build, applies security-extended queries and uploads SARIF evidence. The official v4 annotated tag was resolved to immutable commit `2892aa5e19bbd11bc0cff5427e3b750a04d9e3c2` before pinning. Scan success is not an assertion of zero alerts: the completed analysis and actual alert results must be inspected. Existing three-job platform acceptance remains mandatory.

Existing deterministic Decimal/Risk boundary suites and reducer concurrency fixtures remain required. Coverage percentages and mutation scores are not substituted for them. Automated broad mutation/coverage instrumentation is not added in this increment: it would require new pinned tooling and separate validation; a complete final PHASE 12 review must state the actual evidence rather than claim these reports exist. Branch protection remains the documented manual administration item in the [cross-phase audit](cross-phase-audit.md).
