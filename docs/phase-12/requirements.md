# PHASE 12 — Risk Engine and AMEND requirements

Baseline: clean main `8ccd81df43f1a7e18005d349bf08a0ad45888260`, with [PHASE 11 acceptance](../phase-11/verification.md) and full [CI 37324540510](https://github.com/dendenden-boop/tradeGPTbot/actions/runs/37324540510). Scope follows the [canonical roadmap](../phase-0/implementation-plan.md), [Risk design](../risk-engine.md) and [Portfolio contract](../phase-10/contracts.md). PHASE 13 is not started. LIVE remains disabled and no real exchange mutation is authorized by this phase transition.

## Required modules and acceptance

1. Strict, immutable policy evaluation using canonical decimal strings and complete server-proven state. Platform maxima intersect user maxima with min; minimum protection intersects with max. Missing, malformed, stale, future, conflicting or unsupported evidence never becomes zero or approval. All master-prompt order/position/asset/account/user exposure, concurrent position, leverage, daily realized/total loss, drawdown, order frequency, available balance, price deviation, liquidity and exchange health checks need boundary tests.
2. Certified snapshot construction from reconciled Portfolio/Market Data/account state, with scoped unit conversion, external-flow-adjusted UTC loss baselines, all open/pending/UNKNOWN orders and permanent reservation ownership. No double counting and no guessed parity, equity, collateral or quantity. Restart requires reconstruction, not process-local authority.
3. Durable evaluate-and-reserve with short PostgreSQL transactions and stable user/account/instrument lock order. Two concurrent intents and cross-account user limits cannot overcommit. Exact command/policy/state/rule/capability/permission versions bind immutable decisions. SQL failure, limiter failure and uncertain commit block admission. Expiry blocks dispatch but does not release possibly spent funds.
4. Durable scoped global/user/connection/strategy kill switches and circuit breakers. Half-open permits health/reconciliation probes only. Cancel and independently proved reduction have separate contracts; a reduce-only flag alone does not prove safety. Close cannot cross zero. Protective cancellation and expanding AMEND count as increasing risk.
5. Final dispatch validation against current policy, pauses, health, reservation and ownership, followed by durable attempt and one-use permit. Preserve PHASE 11 permanent replay, immutable PLACE commands, pre-I/O attempt persistence, UNKNOWN and no blind retry. Manual/strategy/TWAP/rebalance/Paper paths will use this same required server gateway; future callers are not implemented prematurely.
6. AMEND was formally transferred from PHASE 11. Define generic semantics and capability mappings first, then implement separate immutable AMEND intent, permanent semantic idempotency, exact target/revision/scope, current metadata, Risk reservation adjustment, attempt, permit and recovery. Never emulate unsupported amendment with separate cancel/create. Test concurrent fills, quantity floor, partial replace, ACK versus outcome, ambiguous dispatch and restart.

## Implementation order and invariants

The first implementation increment is pure policy evaluation plus the semantic AMEND design. A pure evaluation result is **not** a RiskGrant and cannot dispatch, reserve, release or write Portfolio money. The second increment adds durable control lifecycle and a shared final permit/pause ordering gate, with conservative rejection of unclassified mutations. Certified evaluate-and-reserve, current policy/state validation, trusted health recovery and native amendment lifecycle remain mandatory before phase acceptance. No public HTTP trading/control endpoint or client-trusted tenant/credentials/URL is introduced. Existing production adapters remain unsupported for AMEND until their exact contract tests pass.

Tests/contracts precede implementation. New confirmed defects receive RED reproduction before repair. Published migrations remain immutable; any persistence addition uses a new migration and fresh/upgrade/RLS tests. Complete format/docs/lint/typecheck/unit/HTTP/build/schema/runtime/clean/audit, native PostgreSQL and Ubuntu/Windows/real-services CI are required. **READY FOR PHASE 13** requires every module above, including AMEND, rather than only a green pure-rule suite.
