# PHASE 6 — Bybit Adapter contracts

Scope and acceptance: [requirements](requirements.md), [verification](verification.md). Factory: [index](../../packages/exchange-bybit/src/index.ts); trusted integration ports: [ports](../../packages/exchange-bybit/src/ports.ts). The adapter implements the existing 33-operation [Exchange Core contract](../phase-4/contracts.md), without changing its authorization, decimal, registry or stream semantics.

The factory now requires a server-injected RuntimeInstrumentRegistry with get/put after the reproduced cross-adapter lifecycle defect. There is no implicit reference default. Read/write semantics and anti-reuse are preserved; reference stores are explicit test/diagnostic fixtures only. See the [durable lifecycle contract and verification](../instrument-registry-lifecycle.md).

## Profiles and authority

| Profile IDs                                     | REST                  | Public WS                                         | Private WS                          |
| ----------------------------------------------- | --------------------- | ------------------------------------------------- | ----------------------------------- |
| bybit-spot-live-v1 / bybit-linear-live-v1       | api.bybit.com         | stream.bybit.com/v5/public/spot or linear         | stream.bybit.com/v5/private         |
| bybit-spot-testnet-v1 / bybit-linear-testnet-v1 | api-testnet.bybit.com | stream-testnet.bybit.com/v5/public/spot or linear | stream-testnet.bybit.com/v5/private |
| bybit-spot-demo-v1 / bybit-linear-demo-v1       | api-demo.bybit.com    | mainnet public WS                                 | stream-demo.bybit.com/v5/private    |

Only these immutable global profiles are accepted. There is no automatic host rotation, regional fallback, redirect following, environment switching or WebSocket trading endpoint. Mainnet Demo is separate from testnet Demo. A forbidden endpoint never becomes permission to try another host.

`connection.resolve` captures the server account and credential reference. `credentials.resolve` must return that exact account/profile binding. `permissions.verify` must provide verified UID/profile/reference evidence with `canRead=true`, explicit trade permission, withdrawal disabled, checkedAt not in the future, age and validity no longer than 30 seconds. Permission expiry is checked again after credential resolution. These ports are trusted server services; caller supplied account hints or test fixtures are not enrollment proof. A real permission/enrollment implementation is not provided by this package. Demo does not expose `/v5/user/query-api` in its documented whitelist, so native account info alone cannot prove UID/key permissions. It additionally verifies UTA 2.0/Pro, cross/isolated margin, no spot hedging and no master trader. Linear position reads and mutations verify native positionIdx=0 for the selected instrument. AccountInfo ONE_WAY names the admitted profile; it is not proof of a global mode across unselected symbols, since Bybit mode can differ by symbol.

Capability evidence is dated, profile-bound and must match Core admission. Evidence cannot override hard unsupported features or enable LIVE mutations. No adapter is connected to the application API or a financial writer in this phase.

## Admission, signing and outcomes

New-risk admission requires current rules, known constraint fields, Core rule validation and the trusted `orderAdmission` port inspecting complete observed price/lot/leverage/risk constraints. Unknown fields never become supported just because they are primitives. Spot market and limit quantity maxima are distinct; deprecated fields do not replace active constraints. Metadata/admission fingerprints, permit and permission expiry are rechecked immediately before dispatch, after asynchronous rate, credential and admission calls.

Every mutation also requires Core's command hash/profile/account/expiry checks, trusted authorization and an explicit sandbox grant. These are server integration boundaries, not a Risk Engine implementation. LIVE mutations always fail closed. No real TESTNET/DEMO mutation runs without separate account acceptance authorization.

REST HMAC-SHA256 signs exact timestamp + key + recvWindow(5000) + encoded GET query or POST JSON bytes after rate reservation. Private WS signs `GET/realtime{expires}` after control reservation. Clock samples are endpoint-bound, at most 30 seconds old, RTT at most one second and inferred offset at most 500ms. There are no logged secrets or native private error strings.

Native create/cancel responses are ACKNOWLEDGED, never proof of fill/cancellation. ACK IDs must match the requested client/exchange identity. Timeout, abort or connection loss after dispatch, malformed/mismatching ACK, duplicate requests and ambiguous exchange errors produce UNKNOWN. Only known definitive rejection codes become DEFINITIVELY_REJECTED. There is no mutation retry; recovery uses read reconciliation with the same clientOrderId. No result from a canceled/late server port may start an HTTP dispatch.

## Bounded resources and rates

Real HTTP/WS supports AbortSignal and deadlines up to 30 seconds. HTTP destroys canceled sockets; WebSocket close forces termination after 250ms. Transport promises settle and Core releases pending slots after actual settlement. Limits: 16 HTTP requests, 16 WS sockets/sources, 2MiB response body, 16KiB response headers, 1MiB WS message, 64KiB outgoing buffer / 16 queued sends; compression disabled. Native private order deduplication tracks at most 64 identities and resyncs on overflow rather than dropping observations.

The mandatory rate port atomically covers shared egress-IP, UID, category, route, request/order and WS connection/control budgets using actual account evidence and response headers. Local HTTP 403 backoff is ten minutes; HTTP 429 / native 10006 backoff is at least one second, incorporates bounded native reset time and applies before awaiting an observer. Private signing happens after admission waits. WS auth and subscribe ACKs are mandatory before DATA. Native Linear snapshots may arrive before subscribe ACK: at most 16 matching frames / 1MiB total are buffered and released only after success; failure/abort/overflow discards the buffer and closes the source. Heartbeat is budgeted every 20 seconds. Gap, overflow, close or malformed controls terminate with resync. Reconnect/backfill orchestration belongs to PHASE 9.

## Verification boundary

Protocol fixtures and actual loopback sockets prove deterministic normalization, signatures, bounded settlement and Core integration. They do not prove real key permissions, exchange account mode, liquidity, fills or unrestricted regional access. [Public probe](../../scripts/probe-bybit-public.mjs) uses immutable profiles, bounded read-only requests, no credentials or mutation authorizer, and reports unavailable profiles honestly. Real private acceptance remains separately scoped. Final results and the gate are recorded only in [verification](verification.md).
