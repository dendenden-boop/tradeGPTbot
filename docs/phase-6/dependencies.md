# PHASE 6 — Dependencies and packaging

Bybit reuses the existing pinned Node 24.20.0 / pnpm 11.25.0, Zod 4.5.4, ws 8.22.0 (MIT), @types/ws 8.18.2 (MIT, development only), and workspace Exchange Core. The [lockfile](../../pnpm-lock.yaml) adds one workspace importer and changes no pre-existing package versions or integrity entries. No exchange SDK, HTTP retry layer, native optional addon or release-age exception is introduced. Prior dependency evidence remains in [PHASE 5](../phase-5/dependencies.md); the current audit result is in [verification](verification.md).

The native bounded HTTP/WS IO and lossless wire primitives are copied into the adapter from the accepted PHASE 5 implementation and covered locally by real socket tests. This deliberate small duplication keeps completed Binance code unchanged and avoids a shared-transport refactor during Bybit implementation. Exchange Core remains the common DTO/authorization/registry/stream contract; future extraction requires its own compatibility checks.

The sole production runtime export is `createBybitAdapter`. IO, credential signer, endpoint definitions and injectable test assembly have no package subpath exports. The deploy artifact includes dist and runtime dependencies, excludes test/source tooling and is verified independently with a frozen production lockfile, offline package store and external import. The existing clean-install check now validates five deployment artifacts: API, database, Exchange Core, Binance and Bybit. Published migrations and application API composition are unchanged.

Rate admission, permission enrollment, credential retrieval, sandbox grants and durable order identities are server-owned ports. No default implementation authorizes them in production. There is no network access on import or factory construction. Manual `pnpm probe:bybit` performs only public reads with a bounded budget and records sanitized results; it does not install, trade or provision exchange credentials.
