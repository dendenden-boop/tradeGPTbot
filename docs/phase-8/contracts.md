# PHASE 8 — HTX protocol contracts

## Production assembly and profiles

Factory-only runtime export `createHtxAdapter(options)`. RuntimeInstrumentRegistry and atomic shared rate port are required; internal IO/profiles/signers/fixtures are not package subpaths. No IO at import/construction. Trusted optional connection resolves native UID and credential reference; Spot also resolves one explicit numeric Spot account-id. Fresh credentials and permissions must match profile/account exactly. Syntax does not establish trust: only server composition may construct these ports.

| Profile            | Product/account mode                                 | REST                  | Public / private WS                         |
| ------------------ | ---------------------------------------------------- | --------------------- | ------------------------------------------- |
| htx-spot-live-v1   | Spot cash                                            | https://api.huobi.pro | /ws / /ws/v2                                |
| htx-linear-live-v1 | USDT perpetual, single-asset non-unified cross hedge | https://api.hbdm.com  | /linear-swap-ws / /linear-swap-notification |

Environment is always LIVE and mutations are hard denied by Core and factory authorization. No mutation route exists in HTX REST client. A future confirmed sandbox/execution scope needs separate implementation/acceptance; this phase cannot be used to dispatch real orders. Shared-key UID proof for derivatives reads uses only the fixed official Spot /v2/user/uid bridge, signed for that host, with a separately identified route in the shared budget. It cannot accept arbitrary URL/host overrides.

## Native protocols and bounded resources

REST canonical query is sorted by raw ASCII parameter names, RFC3986 encoded, then HMAC over method/host/path/query with newlines. Authentication query includes AccessKeyId, SignatureMethod=HmacSHA256, SignatureVersion=2 and UTC timestamp seconds without Z. POST read business parameters remain solely in JSON body. Spot private WS uses /ws/v2 lower-camel auth fields, signatureVersion=2.1 and unsigned authType. Contracts private WS signs capitalized v2 parameters on its own fixed path. Rate admission precedes secret resolution/signing; fresh 30s clock and proof, RTT <=1s and offset <=500ms, final expiry checks fail closed.

IO independently limits body 2MiB, headers 16KiB, 16 HTTP operations, 16 WS sources, sends 16/64KiB, compressed frame 1MiB and gzip output 1MiB, total operation deadline <=30s, close grace <=250ms. HTTP redirect/upgrade is not followed; WS redirects/compression negotiation disabled. Abort destroys native request/response or terminates WS and settles promises. Bounded server-port waits do not claim to cancel external port implementations: those implementations still own their internal cancellation contract.

Public native gzip `{ping}` returns exact `{pong}`; derivative private `{op:ping,ts}` returns `{op:pong,ts}`; uncompressed Spot private `{action:ping,data:{ts}}` returns matching pong. Every auth/sub/pong consumes shared budget. Spot private heartbeat inactivity allows the documented 20s interval; every subscription is still bound by its request deadline and proof/metadata expiry. No transparent reconnect/replay.

## Observations, metadata, units and admission

Spot settings /v1/settings/common/market-symbols must return full=1, all selected symbols exactly once. Contract-info selects only business_type=swap, empty delivery fields and exact BASE-USDT pair, cross/all support. At most 300 selected instruments. New UUID-based immutable rules/metadata/contract observations commit to the mandatory owner; consumer cache does not replace registry authority. TTL 60s, no stale version after async REST or per WS event. Runtime persistence/anti-reuse requirements remain in [the shared lifecycle contract](../instrument-registry-lifecycle.md).

Spot pp/ap give tick/step; directional static maxima are intersected conservatively. Native dynamic price ratios/turnover and ETP constraints remain explicit admission facts. Every unrecognized field blocks new-risk support. Derivative contract-info proves tick/BASE face value but not native order limits: local integer quantity bounds are resource safety bounds and **never trading permission**. No order admission capability is enabled in PHASE 8.

Native number lexemes survive JSON parsing; exact bounded exponent expansion handles HTX scientific notation without rounding. Big IDs remain strings. Snapshot public books use native timestamp/version when supplied and convert linear level quantity contracts × BASE face value; no fabricated DELTA links/checksum. WS snapshots do not claim incremental continuity. Tickers use native exchange time; absent bids/asks/change/quote volume are unavailable. Candles use base amount; Spot vol is quote, derivative vol is contracts (trade_turnover is quote when available), completion is derived from the closed interval and observation clock. Unsupported timeframes fail; historical Spot uses ranged WS request, derivatives ranged REST without size (which would cause native from/to to be ignored).

Private read evidence validates native UID, working explicit Spot cash account or native non-unified account type + cross USDT dual_side wallet. Fresh trusted account mode is required as well: the legacy numeric type cannot prove the newer collateral mode alone. Derivative global equity is margin_balance; availableToTrade/free/locked are unavailable because per-contract margins and withdraw_available are not global trading availability. Spot complete trade/frozen components must both exist, duplicates/other balance kinds fail; missing amounts are not fabricated zeros.

Ordinary orders require persisted server identity mapping and known client ID, exact native instrument/account/mode and supported type. Spot buy-market cannot become a BASE order. Filled average/fees stay unavailable/empty when the endpoint cannot prove them; execution fees come from fills. Derivative quantity remains whole CONTRACTS, with no offset=both/one-way/algo reinterpretation. Fee convention is common positive cost / negative rebate: native derivative negative charge is inverted, Spot native cost sign is retained. Derivative execution identity combines match_id with native id; match_id alone is not unique. Unsupported manual/unmapped orders cannot be omitted to claim an empty account.

All absent/not-found ordinary lookups return INDETERMINATE, including exchange ID and client ID. FOUND requires the requested ID exactly. No UNKNOWN can be resolved by an expired client lookup or absence, and no POST retry exists. Ordinary and algo IDs remain separate. REST position snapshot time must be within 5s of receipt and no more than 1s in the future, including empty collections; private position streams use the same freshness bounds and conflicting equal timestamps require resync. Derivative native 1032 enters bounded rate backoff; account/input errors do not masquerade as rate limits. Contradictory status/code success envelopes fail closed.

## Pagination and stream lifecycle

Private snapshots have 16 slots, <=2000 rows, <=40 native pages, TTL <=30s/metadata expiry. Native history cursors walk monotonically to an empty page with fixed <=48h/90day window. Spot open-orders cap hit is UNSUPPORTED rather than a truncated complete snapshot; derivative open-pages must retain total size and unique orders. Public metadata cursor is version/offset-bound. Core signs opaque cursors with operation/query/account/profile binding. Private native cursor rotates on each consumption; final page deletes its snapshot immediately; no LRU of live cursors. Concurrent initial reservations count against capacity before fetching.

Auth/subscription ACK precedes DATA. Before ACK <=32 frames/64KiB; controls <=8; private readback queue <=16; dedup/order/candle observations <=256 then terminal resync, never unbounded history. Conflicting ticker timestamp/book version/trade ID or regressed timestamps, corrupt/foreign topics/UID, replaced metadata, expired proof or closed source terminate with resync. Native private order deltas trigger scoped authoritative REST readback; no full common order is fabricated from a partial push. Private balances are deliberately unsupported. Existing Core source-establishment errors are sanitized into UNAVAILABLE; fine-grained protocol limitations are recorded here rather than changing completed Core semantics.

Book streams compare present native versions as bounded canonical unsigned integer strings using BigInt, before deduplication: lower → resync, equal + identical full native tick → ignore, equal + different tick → resync, greater → accept subject to existing time/freshness guards. Previously seen old versions are still regressions. An unversioned frame retains the last known version; it is ordered by exchangeTime: lower → resync, equal + identical full tick → ignore, equal + conflict → resync, greater → accept. Fingerprints include the entire validated native snapshot, not only requested depth and not generated snapshotVersion/receivedAt. Metadata guards run before any duplicate can be ignored; version dedup remains bounded and source resync closes without automatic reconnect.
