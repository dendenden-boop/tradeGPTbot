# PHASE 11 contracts

Server composition binds a verified principal/worker to exact tenant/account/connection/mode/profile. A UUID or structurally valid port is not authorization. Every service operation checks the required authorization port; native observation and fill ingestion require trusted worker provenance. Adapter endpoints and credentials remain server-controlled. PAPER cannot masquerade as TESTNET; TESTNET and DEMO remain distinct. LIVE mutations and Paper simulation are unavailable in this phase.

The durable store creates the original public OrderIntent and Order atomically with permanent request hash and outbox. Account-scoped decimal client IDs come from the locked persistent clientIdHighWatermark, never Number arithmetic or process-local counters. Account epoch/counter recovery must preserve all historical identities; changing an epoch does not authorize resetting the counter. Duplicate keys return the original command; conflicting semantic reuse rejects permanently. CANCEL uses its own immutable intent targeting the placement order. Original PLACE fields never change.

Submit persists RISK_APPROVED then SUBMITTING and a unique SubmissionAttempt before external I/O. Risk policy evaluation is injected, not implemented here. SQL verifies its persisted matching APPROVE/REDUCE_ONLY decision, reservation, permission epoch, state/capability/rule freshness and exact scope. Claim serialization and one-use adapter authorization prevent two workers from dispatching the same command. No transaction spans exchange I/O. Crash after the durable claim requires reconciliation, including when dispatch itself cannot be proven. UNKNOWN never triggers blind retries. Cancel permission is separate and also passes the mandatory boundary.

Principal authorization is checked again after durable claim persistence, immediately before adapter invocation. A known rejection before invocation is recorded as definitive; an exception after invocation is UNKNOWN. The durable transport authorizer rejects expired or future-issued permits, permits extending past the saved attempt deadline, and permits expiring while waiting for its atomic consumption.

ACCEPTED is acknowledgment, not proof of fill/cancel completion. Positive scoped order lookup supplies lifecycle observations. NOT_FOUND/INDETERMINATE, incomplete history, stale metadata and gaps keep reconciliation required. Restored unresolved attempts are never resent. Native timestamps are durable per-order watermarks: old snapshots are ignored, identical duplicates idempotent, equal-time conflicting content rejected. Cumulative fills cannot regress; terminal orders cannot reopen. A fill arriving after a terminal snapshot is adopted only if consistent with that snapshot's executed quantity.

Portfolio is the monetary writer. Execution ingestion first commits through the certified PHASE 10 source; Order Engine then atomically adopts its journal identity and existing ledger ID into public fill/fee and execution adoption evidence. No ledger insertion, update or retroactive fillId attachment is performed. This avoids double accounting and respects immutable ledger history. Adoption requires exact account/mode/instrument/native exchange-order identity, metadata mapping and payload hash; original observed internal UUID alone is not authority. Public order filledQuantity is the maximum of positive native cumulative quantity and adopted execution quantity, not their sum. Complete status requires causal order evidence and matching execution coverage; a quantity total alone is not a universal exchange history proof.

All amounts are canonical decimal strings. Weighted average execution price uses the existing 100-digit decimal context with explicit 18-place rounding. Immutable rule versions map native version strings to public DB UUIDs through server-persisted rules.version. Unsupported or ambiguous mapping fails closed. Public order is authoritative for lifecycle; execution sidecars retain only immutable command envelopes, native observation watermark/fingerprint, journal identities and monetary adoption links.

Hot work and history pages are bounded; durable deduplication/adoption history is never LRU-pruned. Owned operations retain capacity until underlying promises settle after abort. Injected authorization/risk/fill ports must physically settle within their finite budget. PostgreSQL destroys its owned socket on abort; commit ambiguity requires reread/reconciliation. Shared adapter/store/registry disposal belongs to composition. Transactional outbox publication contains IDs/state only and downstream consumers persist an inbox before acknowledgment. Retention, backups and certified worker provisioning remain operator requirements.

Fresh bounded history plus a positive matching final order lookup explicitly completes reconciliation. It may resolve a gap when the native updatedAt is unchanged; identical observations alone do not clear a gap. Native UNKNOWN cannot resolve an attempt. Definitive PLACE rejection is terminal and consistent without imaginary exchange history; definitive cancellation rejection still requires positive order reconciliation. Quantity coverage also requires the native cumulative average to match the adopted execution average at the documented 18-place rounding; mismatch remains blocked. Only NET position admission is supported because the current common NewOrder command has no native hedge-side field.

CANCEL uses current server-persisted rules in its own intent/Risk proof, while the original PLACE command/rule identity remains immutable. Cancellation checks current registry freshness/replacement and the cancellation rule version, without applying new-order size/price admission to historical placement fields. Previously attempted cancellation keys return their durable state and never dispatch twice.

Positive recovery also requires native creation time at or after the persisted intent. An old native order sharing a client ID is not proof of the new command. Inconclusive timestamps or an unproved clock model remain reconciliation-required; client counters and external account ownership must survive restore without resetting historical identity.
