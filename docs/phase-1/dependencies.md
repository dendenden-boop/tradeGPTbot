# Зависимости PHASE 1

Срез: **2026-09-05**. Версии и лицензии ниже прочитаны из установленных `package.json` и сопоставлены с manifests проекта. Полный граф и integrity-хэши закреплены в [pnpm-lock.yaml](../../pnpm-lock.yaml). Результаты сборки, typecheck, тестов и security audit публикуются отдельно в [отчёте проверки](verification.md); этот документ не объявляет эти проверки успешными.

Размеры измерены суммой размеров обычных файлов в установленном пакете, без его `node_modules` и без перехода по символьным ссылкам. Сюда могут входить декларации, исходники, документация и тесты поставщика. Это не размер загружаемого кода, не весь транзитивный граф и не потребление RAM.

Клиентского bundle в PHASE 1 нет. API собирается `tsc` в ESM и загружает зависимости в Node.js. Zod используется при старте; валидатор конфигурации не выполняется на каждом health-запросе. PostgreSQL/Redis проверяются параллельно, с таймаутами, общим выполняющимся запросом и ограниченным кэшем. Производительность приложения требует отдельных нагрузочных измерений. Проверенный 6 сентября runtime-образ имеет Size **83 563 830 байт** по `docker image inspect`; image ID и границы измерения приведены в [отчёте проверки](verification.md).

### Популярность и сопровождение

На официальных GitHub-страницах на дату среза отображались приблизительно **37,1 тыс.** stars у Fastify, **43,8 тыс.** у Zod, **18,2 тыс.** у Pino, **13,2 тыс.** у node-postgres и **15,3 тыс.** у ioredis. Ссылки в таблице ведут на эти страницы. Это сигнал размера сообщества, а не число production-установок или гарантия качества. Статистика npm downloads недоступна в текущем web-инструменте и не подменяется оценкой.

Fastify публикует [политику LTS и поддержки Node.js](https://fastify.dev/docs/latest/Reference/LTS/); для ветки 5 дата окончания LTS в таблице пока не указана. У Zod, Pino и node-postgres есть публичные исходники, документация и issue/PR-процессы; поддержка выбранной комбинации дополнительно проверяется нашими typecheck и тестами. Обязательства по коммерческому SLA для этих пакетов не заявлены.

ioredis 6.0.0 опубликован **31 июля 2026 года**: требует Node.js 20+, по умолчанию использует RESP3 и включает исправления подключения/типов. Node.js 24 удовлетворяет заявленному ограничению. Совместимость `PING`, аутентификации и восстановления с закреплённым Redis подтверждена реальными integration-прогонами 6 сентября; результаты приведены в [отчёте проверки](verification.md). Источник: [release notes ioredis 6.0.0](https://github.com/redis/ioredis/releases/tag/v6.0.0).

Точные SHA-256 image digests закреплены в [Dockerfile](../../infra/Dockerfile), [development Compose](../../infra/compose.dev.yml) и [test Compose](../../infra/compose.test.yml). Digest фиксирует выбранный артефакт; обновление безопасности требует явного обновления digest и повторного прогона проверок.

Лицензия Redis-сервера отличается от MIT-лицензии клиента ioredis. Для будущей коммерческой поставки нужно зафиксировать выбранную лицензию Redis и способ распространения/эксплуатации; bootstrap использует неизменённый официальный сервер в локальной среде. Текущий документ не выдаёт заключение о соответствии ещё не определённой коммерческой поставки.

## Контроль зависимостей

Прямые версии закреплены точно, `strictPeerDependencies` и `engineStrict` включены. `minimumReleaseAge: 1440` задерживает выбор совсем новых публикаций при разрешении зависимостей. Настройки находятся в [pnpm-workspace.yaml](../../pnpm-workspace.yaml); build script разрешён только для `esbuild@0.28.2`, которому нужен платформенный исполняемый файл для Vite. Общее разрешение lifecycle scripts не включено. Назначение настройки описано в [документации pnpm](https://pnpm.io/settings).

`pnpm audit:dependencies` проверяет граф по advisory-данным npm и завершает проверку с ошибкой для найденных high/critical проблем. Такой audit не заменяет анализ API, логов и образов. Результат конкретного прогона, включая недоступность сети, фиксируется в отчёте проверки.

Prisma, BullMQ, Next.js, библиотеки авторизации, decimal-арифметики и SDK бирж в PHASE 1 не установлены: каждому из них нужен отдельный выбор и проверка на своём этапе. Текущий `pg` нужен для реальной проверки зависимости до появления схемы БД; он не создаёт таблиц и не запускает миграции.
