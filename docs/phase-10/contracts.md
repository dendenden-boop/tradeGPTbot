# PHASE 10 contracts

## Trust and ownership

`@ctp/portfolio` is a server library with required durable store, runtime InstrumentRegistry, authorized account binding, authorization port and read-only reconciliation source. Account bindings come from a server authorization resolver after checking the authenticated principal and connection ownership. The mandatory authorization port checks ownership/permission revocation on every operation; it is bound to a verified server session/worker grant, never a request-body tenant. Syntactic UUID validation is not authorization. There is no HTTP portfolio route or default reference store. Read-only account observations may use LIVE profiles, but this package contains no exchange mutation capability.

A binding identifies tenant/account/mode, native external account, exchange/region/environment/market and a server wallet ID. One wallet has exactly one primary portfolio book. Different credentials for the same native account do not create extra balances; overlapping cross-product wallets must be resolved by the server wallet coordinator before registration. Unified views reject duplicate wallet books and mixed PAPER/TESTNET/DEMO/LIVE totals. Credentials remain inside the existing adapters. Source ports must prove their permissions, metadata, pagination completeness and bounded cancellation.

## Snapshot and delta cut

The durable store serializes each account wallet using a row lock and revision. An economic event has a permanent scoped identity and semantic fingerprint; receivedAt is not part of identity. Equal replay has no effect; conflicting reuse fails closed. The in-memory projection has at most 2000 unreconciled economic identities, 1000 positions/assets and 1000 commitment overlays; historical deduplication remains durable and is never LRU-evicted.

Reconciliation first reads the committed revision and pending identities, then calls the injected read-only source outside the SQL transaction. The source must provide an absolute complete snapshot and proof that it includes exactly those pending economic events, including fees/funding. The commit requires the original revision; a concurrent fill invalidates the cut. A timestamp or REST response alone is not coverage proof. Source implementations without provable snapshot/history overlap remain stale; the generic engine cannot infer a universal exchange cursor.

The source receives `pendingEvidence` with the original native fill/funding IDs, identity namespace and existing ledger links, fetched in bounded batches of 200. Missing journal evidence fails reconciliation. Fill identities hash the canonical tuple `[kind, identityScope, instrumentId, nativeId]` within the account book; wallet ownership is enforced separately. Coverage checks must use native history, rather than trying to reverse the hash.

Balances become the authoritative new anchor after proven coverage, rather than adding the same fills again. Position quantities are compared with the local cost-basis projection. Differences are retained as reconciliation discrepancies and block freshness; they never synthesize fills/PnL. Initial positions may have unknown cost basis. Subsequent repair requires an explicit trusted basis observation, not a guessed price. Snapshot identity reuse with a different payload is rejected. Restored snapshots are stale until a fresh reconciliation succeeds.

The snapshot cut is inclusive. A previously unseen economic event at or before that cut is rejected for reconciliation, not added to the absolute balance. Durable identical events are recognized before applying this rule. Subsequent economic input must not regress event time; a trusted source coordinator supplies causal order for equal-time executions. An ambiguous/late source requires history recovery, never guessing order-dependent cost basis from arrival time.

Opening native balances and later observed cash differences post against EXTERNAL counteraccounts in the existing immutable ledger. An unexplained difference is ADJUSTMENT evidence, not trading income, and remains UNRECONCILED across repeated snapshots. The source may explicitly acknowledge the latest snapshot ID through `repairFrom` after investigating history. A changed position is rebased only under this explicit acknowledgment; native entry-price evidence supplies its new basis, while historical realized PnL becomes unavailable rather than fabricated. Existing fees/funding evidence remains preserved. The append-only event journal retains both the discrepancy and the repair. These are read-only reconciliation observations, not exchange transfer/withdrawal commands.

## Accounting and valuation

All monetary fields are canonical decimal strings. Exact add/subtract/multiply reuse Exchange Core bounds; division for pro-rata basis uses a private 100-digit Decimal context and explicit HALF_EVEN at 18 places. Remaining basis is retained exactly, and the final close consumes the entire remainder. Open and realized gross PnL are separate from fees/funding; net is unavailable if any cost lacks a proven quote conversion. Base-asset fees use the execution price, quote fees use their amount, and third-asset conversions require timestamped trusted evidence. No stablecoin parity is assumed.

Spot principal moves base/quote holdings. Linear derivatives move settlement cash only for realized PnL, fees and funding; leveraged notional is never added to wallet assets. SHORT quantities are internally signed, hedge LONG/SHORT buckets cannot reverse; NET may cross zero. Contract quantities require fresh immutable BASE face-size metadata. Native and local realized PnL are separate observations; local PnL starts at the imported accounting anchor, not an invented lifetime history. External inventory changes invalidate unsupported cost basis rather than manufacturing gains.

Pending/unknown/reserved overlays are observations of future Order/Risk ownership, not a reservation allocator. Only unreflected holds reduce the reported conservative spendable estimate; native locked funds are already inside total. UNKNOWN remains explicitly blocking until trusted reconciliation resolves it. Portfolio does not authorize orders.

Price evidence carries asset/quote, source identity, event time and freshness; derivatives unrealized PnL requires MARK evidence. Stale/missing price or balance preserves a visible estimate/partial sum with unavailable complete value. Empty wallets value to zero; zero exposure needs no fabricated price. No arithmetic mixes currency units without evidence.

MARK evidence must match the complete exchange/region/environment/market scope and native instrument, not only the base asset. Fee FX evidence cannot be in the future and must be within five seconds of the execution. A server quote consolidator selects unambiguous LAST conversion evidence; valuation refuses multiple candidates. Spot reconciliation compares the sum of currency-qualified lots for each base asset with the observed wallet inventory. Cross-quote disposal of a different lot requires an explicit evidenced cost-basis transfer; it cannot invent historical FX basis.

## Persistence

Derivative `Balance.total` is static wallet cash including realized cash effects, excluding unrealized PnL. Portfolio adds scoped MARK unrealized PnL once. HTX uses native `margin_static` and requires fresh `margin_static`, `margin_balance`, `profit_unreal` with exact `margin_balance = margin_static + profit_unreal`; missing/stale/inconsistent evidence is rejected. The official [HTX linear API contract](https://huobiapi.github.io/docs/usdt_swap/v1/en/) defines these fields. Binance/Bybit/OKX balance mappings are unchanged.

Each hold ID has a durable per-book watermark containing trusted coordinator timestamp, semantic SHA256 fingerprint and terminal release/UNKNOWN flags. Timestamp is the version: older updates/releases are ignored; equal timestamps require identical semantics; newer events advance the watermark. Event ID reuse is independently protected by the permanent journal. Released identities are terminal even for newer COMMITMENT: a new reservation requires a new ID. UNKNOWN permits only an identical hold observation or a newer RELEASE with trusted `resolved=true`. Distinct state changes require strictly increasing coordinator timestamps; ambiguous equal-time updates fail closed.

The writer loads only the relevant watermark under the existing book lock and atomically commits evidence/checkpoint/outbox. Ignored or semantically identical events are journaled without revision/publication or money effects. Identical event ID replay is also a no-op. Watermarks/tombstones are never evicted or deleted; restart does not reset them. The reducer requires a supplied durable watermark or explicitly proven absence. The SQL trigger prevents timestamp regression, equal-version conflicts, terminal reopening and unproven UNKNOWN weakening.

Additive `202610050001_portfolio_hold_ordering` retains all legacy hold IDs. Old arrival order cannot prove safe amounts, so affected projections become GAP and active holds UNKNOWN. Historical fingerprints/postings remain unchanged. Each legacy identity requires a newer trusted RELEASE; later reservations use new IDs. Owner-only backfill uses transactional DDL locks and restores FORCE RLS before commit. This quarantines unproven history rather than inferring a financial repair.

Storage TESTNET/DEMO/LIVE must exactly match market environment. DEMO+TESTNET and TESTNET+DEMO fail closed. PAPER is a separate simulated storage mode using a server-selected public market profile, since Core has no PAPER market environment. PostgreSQL joins account and connection using exact mode. Legacy contradictory bindings are rejected and never automatically relabeled without authoritative account provenance. Unified views keep all four storage modes separate.

An additive schema stores bounded account projections, permanent event fingerprints and a bounded delivery outbox under FORCE RLS. A restricted portfolio login has no credentials/auth/order/risk mutation privileges. Each event atomically commits evidence, append-only conserved postings in the existing ledger, position/balance checkpoint and publication event. The PHASE 11 order-linked `public.fill` is not fabricated: native portfolio fill evidence retains its execution identity and internal order reference for later owner integration. Existing ledger constraints remain authoritative.

Each outbox record includes both the delivery UUID and immutable journal `eventId`. `evidence(binding, ids, context)` returns the original event and `ledgerId`; acknowledging delivery does not remove this proof. Future execution owners must adopt that posting for the same native execution, rather than applying its cash effect again. This contract does not implement the future Order Engine.

Transactions have finite connection/query/operation budgets and destroy the owned socket on abort. Unknown commit outcome requires an authoritative reread and identity reconciliation; it is never treated as permission to dispatch another exchange mutation. Delivery is at least once with persistent event IDs. Downstream inbox acknowledgement is required. Disk retention/backup remain operator policies; bounded hot state is not a deletion policy for accounting history.
