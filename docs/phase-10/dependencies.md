# PHASE 10 dependencies and operations

Node, pnpm and package versions remain pinned. Portfolio adds a workspace importer using the existing Exchange Core, Decimal.js 10.6.0, pg 8.23.0 and Zod 4.5.4. No exchange/private transport dependency or destination is introduced.

The server provides a durable store, certified runtime registry, authenticated account resolver/authorization port and read-only source coordinator. The authorization port must verify connection ownership, account profile and current permissions on every call. Reference stores/registries in tests are not runtime defaults. Source coordinator certification must demonstrate snapshot/history coverage, causal ordering for equal-time executions, pagination completeness, historical fee FX provenance and physical settling after abort. A source lacking these proofs remains stale; it cannot substitute an always-true coverage assertion. Account close waits for owned operations to settle after cancellation; shared store/registry disposal belongs to the composition owner.

Apply additive migration `202610040002_portfolio` using the migration owner. Provision a separate restricted LOGIN member of `ctp_portfolio`, with no membership in API/auth/ingest/signer or privileged PostgreSQL roles. Supply its DSN from server secrets; production requires verify-full TLS. Never route portfolio DSNs, bindings or raw events from HTTP input. No credentials, withdrawal/transfer execution, risk reservation allocator or trading route is exposed.

The existing ledger remains the immutable monetary source. The portfolio schema stores native observation evidence and bounded projections/outbox. Journal fingerprints are permanent across restart; never delete them to reclaim hot capacity. Back up both ledger and portfolio schema consistently. Outbox delivery is at least once, ordered by wallet revision; downstream owners persist their inbox before acknowledgment. PHASE 11 must adopt the existing native evidence/posting for a known execution instead of creating a second fill ledger effect. Order-linked `public.fill` remains the Order Engine's ownership boundary.

Monitor stale reconciliation, discrepancies, unknown commitments, pending economic identities, state bytes, outbox backlog and transaction latency. A blocked/uncertain commit is recovered through authoritative state/identity lookup, never a new exchange POST. The store caps four connections, 1s connection acquisition, 2s statements, 2.5s queries and 3s operations; aborted owned connections are destroyed. Hot state is <=1MiB/wallet; pending identities <=2000, assets/positions/holds <=1000 each, outbox <=10000/wallet. Delivery batches/acks <=200; unified views <=100 wallet books and 2000 price evidences. History/disk retention, recovery source availability and application worker provisioning require operator policies; they are not silently replaced by test doubles.

Current accounting is Spot and BASE-face linear perpetual. Inverse/dated accounting needs a separate capability gate. Unknown cost basis and missing historical fee conversion remain unavailable. Reconciliation rebase is an explicit acknowledged observation and does not invent missing historical PnL. Cross-quote disposal requires a proved lot/basis transfer. This phase implements the library and durable writer, not the future API/UI/Order/Risk/Paper composition or commercial production readiness.
